# 踩坑清单（都是实际翻 16 页 IEEE 双栏论文时踩出来的）

## 抽取

1. **双栏会串行**。`page.get_text()` 默认按 PDF 内容流顺序，两栏会交织。必须按 block 的 `x0` 分左右栏，再在栏内按 `y0` 排；横跨栏间空白的块（通栏图、表、标题）要单独成"带"，排在最前或最后，不能简单归到某一栏。
2. **页眉页脚会混进正文**。"Authorized licensed use limited to…"、会议名、页码每页都有，抽完必须过滤，否则会被翻译一遍。
3. **图注锚定裁图要排除子图注**。`Fig. 1: …` 上方往往先有 `(a) …` `(b) …` 三条子图注，计算"图区上边界"时若把它们算进去，图区高度只剩几个点，图就裁不出来或裁成一条缝。规则：跳过 `^\([a-z]\)` 的块。
4. **同一图号会出现多次**（正文里提前引用 + 图下方真图注），按图号去重，保留第一次命中的。
5. **图注可能在图上方**（部分期刊/海报），此时用"图注下方最近块"作为下边界兜底。
6. **断词**：`hard-` 换行 `ware` 要拼接；但 `coverage-guided` 这种真连字符不能拆。判据：行尾 `-` 且下一行以小写字母开头 → 拼接；否则保留。

## 文本与编码

7. **别让 PowerShell 的 `Get-Content`/`Set-Content` 改写带中文的源码或 Markdown**。Windows 中文环境默认按 GBK 往返，会把 UTF-8 中文写成乱码，甚至吃掉后面的引号。用 Python 的 `io.open(..., encoding="utf-8")` 或 `write` 工具。
8. **一个坏字符能吞掉整片 CSS**。`content: "▎"` 被二次编码成 `"鈻?` 后引号丢失，CSS 字符串未闭合，后面的 `.sh-en { display:block }` 整条规则失效，标题和英文副题挤在一行。**改完 CSS 一定重新渲染首页看一眼**。
9. **`--print-to-pdf` 里别用 `position: fixed` 页脚**。Chrome 会把 fixed 元素定位到页首，甚至单独多出一页（我第一版 18 页里就有 1 页只印了一行页脚）。要页码就用 Chrome 自己的 header/footer 模板，或干脆不要。

## 排版

10. **表格标题和表格必须包在同一个 `break-inside: avoid` 容器里**，否则标题留在上一页底部、表格跑到下一页（表 I 就中过）。
11. **参考文献用悬挂缩进**：`text-indent: -1.75em; margin-left: 1.75em; text-align: left`。默认的 `text-align: justify` 会让只有一行的短条目被拉成"词—词—词"大间距。
12. **Python-Markdown 的嵌套列表要 4 空格**。子代理常写 2 空格，渲染出来会被拍平成同级。渲染前统一 `re.sub(r"(?m)^ {2}(?=[-*] )", "    ", text)`。
13. **插图 `max-height` 别超过 120mm**。竖长的三联图（例如 1063×1499 像素那种）按原尺寸会占掉半页，留出大片空白；限制高度后配合 `break-inside: avoid` 效果最好。
14. **页数比是版式的体温计**。译文页数 / 原文页数落在 0.8–2.2 之外，通常是字体没生效（比如中文字体缺失回退成方框）或图片尺寸失控。

## 流程

15. **重复图占位要手工去重**。切块边界处的图注容易被前后两个子代理各放一次（自测时就出现过同一张图在两块里各有一份），装配时用 `drop_fig` 去掉一份。
16. **首尾要裁掉重复内容**。chunk_1 带标题/作者/单位，而封面区由 manifest 的 `title/authors/affil` 统一渲染，所以 chunk_1 要用 `start_at: "## 摘要"` 裁掉前半段。
17. **参考文献不要交给子代理翻译**。直接按 `[n]` 起头切条、拼行（含断词）、保留英文原貌，作为单独一个 part 排。
18. **图注文本里别留 Markdown 强调符**。`**图 3**：` 里的粗体会进 `figcaption`，视觉上没问题，但如果图注里再套表/图引用会解析错，保持纯文本最稳。

## 不适合这套流程的输入

- **扫描件 / 图片型 PDF**：没有文本层，得先 OCR，抽出来也没有图注 bbox。
- **海报 / 单页 infographic**：文字按视觉框散落，抽取顺序全乱，需要模型按语义重组（可以，但别指望脚本自动分块）。
- **公式密集的理论论文**：公式抽取会丢上下标，重排后要人工核对；必要时保留原页截图对照。
- **必须"原版式"交付的场合**（作业、存档、期刊回稿）：这套是**重排**路线，产出是阅读版，不是复刻版；保版式是另一条更难的路线，别在这里硬凑。

## 渲染细节（Chrome 特有）

19. **Chrome 不认 `break-after: avoid`**。标题照样停在页底、正文翻页（自测第一版就有两处：章节标题孤零零留在页脚）。只能靠 `break-inside: avoid` 的包裹块兜住：`build_pdf.py` 里的 `keep_with_next()` 会把 `h2/h3` 和紧随的第一个内容块（`p`/`ul`/`figure`/`.tblwrap`）包进 `.hkeep`。改渲染逻辑时别把这一步去掉，改完用 `qa.py` 看"页末检查"是否归零。
20. **缩略图必须人眼看一遍**。`qa.py --sheet` 生成的 contact sheet 能一眼看出孤立标题、图注贴错图、页底大片空白、表格被切成两半——机械检查只会报"可疑"，最后一道永远是眼睛。
